# Kari-San: каталог та адміністрування

Вітрина: `/`. Керування: `/admin.html`.

Попередню демонстраційну Supabase-адмінку збережено у `docs/legacy-admin/`; її старий URL `/admin/` веде до нової адмінки. Локальні демо-дані у браузері не видаляються, але не імпортуються автоматично до живої бази.

## Доступ

За прямим запитом власника використовується спільний вхід за поштою та паролем. Кожен, хто знає обидва значення, може керувати каталогом з будь-якого пристрою. ChatGPT для цього не потрібен.

У середовищі Sites: `ADMIN_LOGIN_EMAIL` та секрет `ADMIN_PASSWORD_HASH`. Пароль не зберігається у відкритому вигляді. Хеш PBKDF2-SHA256 із випадковою сіллю, 100000 ітерацій. Для зміни пароля створіть новий хеш через `scripts/create-admin-password.mjs` (пароль передається через stdin), оновіть секрет та опублікуйте версію. Старі сеанси втратять доступ після зміни хеша чи пошти. Самостійне відновлення через email поки не підключене.

Сеанс триває 12 годин: випадковий токен у Secure/HttpOnly/SameSite cookie, у D1 лише його SHA256-хеш. Вихід видаляє сеанс на сервері. Запис захищено перевіркою Origin. Після 10 спроб входу з однієї адреси в межах 15-хвилинного вікна сервер обмежує наступні спроби. Без налаштованих облікових даних редагування закрите.

## Дані

- D1 `DB`: `products`, `settings`, `admin_sessions`, `login_attempts`. Історичну таблицю `admins` збережено, але вона більше не надає доступу. SQL-міграції у `drizzle/` створюють лише схему.
- R2 `BUCKET`: завантажені фотографії, до 5 МБ, JPG/PNG/WebP.
- Існуючий каталог з 84 товарів: `data/catalog-seed.json`. Це знімок джерела, не синхронізація поточних цін/залишків.
- До першого входу API повертає початковий знімок. Під час входу він одноразово переноситься у D1 атомарною операцією. Подальші публікації не перезаписують зміни власниці.
- Архівування приховує товар, але зберігає його для відновлення. Архів відкривається перемикачем у списку; зніміть прапорець архіву в картці та збережіть.
- Експорт каталогу завантажує JSON із товарами та версіями. Це ручна копія, не автоматичне резервування і не експорт самих фото.
- Заміна фото не видаляє старий файл. Автоматичне очищення та імпорт резервної копії ще не реалізовані.
- Перед запуском продажів власниця має перевірити ціни й залишки.

## Розробка

Статичні файли перенесено з `dist/` до `public/`; `dist/` тепер результат збірки. Відео та дизайн збережені. Legacy-скрипти імпорту працюють тільки з початковими файлами, не з живою базою. Не запускати їх для оновлення живого каталогу.

`node --test tests/*.test.mjs` — перевірки каталогу та паролів. `tests/api-local.mjs` — інтеграційні перевірки тільки на `127.0.0.1:5173`, після локальних міграцій та налаштування тестового логіна `test@sites.test` / `local-test-password-only`. Тестові cookie, `.dev.vars` та локальна D1 ніколи не публікуються.

Доставка, приймання замовлень і оплата — окремий наступний етап. Ця адмінка керує товарами, а не замовленнями. Існуючий адаптер доставки у `integrations/` ще не підключений до production.
